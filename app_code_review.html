Security (resolved)

High Fixed 1 · HTML/JS injection

All AI- and ticket-derived strings are now passed through html.escape before reaching any unsafe_allow_html sink or the downloadable report. Covered: subject (+ translation), opportunities, next steps, problem/summary/insights, timeline table, device/customer grids, and the cached-report panel. The on-screen helpers kv() and detail_row() now escape their values internally.

Verified: a ticket subject of Bad <img src=x onerror=alert(1)> appears in the report as &lt;img src=x onerror=alert(1)&gt; — inert text, not an executable tag.

Portability (resolved)

High Fixed 2 · Logo path

_APP_DIR = os.path.dirname(os.path.abspath(__file__)) then PILImage.open(os.path.join(_APP_DIR, "router_nobg.png")). The app no longer depends on a fixed Desktop location and will load on a clone or deployment.

Maintainability & Duplication (resolved)

Medium Fixed 3 & 4 · Chart and actions duplication

Three new module-level helpers now back both surfaces:

  • build_interaction_figures(timeline) → (Sankey, donut, swimlane). The report serialises with to_html; the app passes the same figures to st.plotly_chart.
  • build_dot_timeline_figure(timeline) → the dot timeline, shared identically.
  • iter_update_actions(ticket) → one generator of (name, date, description) rows for both the on-screen "What Happened?" list and the report's actions block.

The previously divergent CRITICAL_KW lists are now a single constant, and the persona/colour maps live in one place.

Low Fixed 7 & 9 · Persona logic

The three copies of _grp() and the name-based _persona_style() (which hardcoded staff first names) are gone. A single persona_group() / persona_style() with PERSONA_COLORS / PERSONA_BG / PERSONA_ICON maps is used everywhere — no more per-name special-casing.

Data & Robustness (resolved)

Medium Fixed 5 · DB upsert

save_report_to_db now runs DELETE FROM executive_reports WHERE ticket_id = %s before the insert, so each ticket keeps exactly one current report instead of accumulating stale duplicates.

Medium Fixed 6 · Silent failures

find_report_in_db and the auto-save block now log via logger.warning(...); the auto-save path also surfaces a ⚠️ toast so a DB problem is visible rather than swallowed.

Low Fixed 11 · Pagination

fetch_all_updates stops on an empty batch, honours count when pagination metadata is present, and has a 100-page safety cap — no premature stop when page_info is missing, no infinite loop if the endpoint never paginates.

Bonus Fixed + · Non-dict update guard

Verification surfaced that _build_agents_html, _get_csat_data, and _build_gap_analysis iterated updates without the isinstance(u, dict) guard the actions code documents — a crash if a cached fake ticket ever carried integer placeholders. The guard was added to all three.

Cleanliness & UX (resolved)

Low Fixed 8 · Dead code  ·  10 · Token usage  ·  12 · Secrets

  • 8 — the unused parse_ts() function was removed.
  • 10 — Claude token counts are stored in session and shown as a caption (🧮 Claude usage: N input · N output tokens) in the Ticket Overview.
  • 12 — credential loading is wrapped in try/except KeyError that shows a clear st.error naming the missing secret and calls st.stop(), instead of a raw traceback.

Intentionally not changed

Note 13 · v() and the value 0

Left as-is. v(0) still returns "—". Changing it risks altering the intended placeholder display for genuinely empty fields; flagged for awareness only.

Note 14 · Single 1,900-line module

Left as-is. Splitting into happyfox / db / analysis / report / charts modules is a larger architectural change; the duplication that made it painful has been removed, so a future split is now easier.
